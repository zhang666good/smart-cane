# 智能助行拐杖（暖杖随行 WarmCane）技术方案 / 架构文档

> 依据《智能拐杖应用方案(1).docx》需求。
> **v0.2 —— 端云分工重构版**：设备端仅做"数据输入/输出"，全部智能处理（AI 对话、音频合成、
> 传感器融合与综合决策）集中在**自建云端服务**。
> 版本：v0.2（技术方案评审稿）

## 1. 方案总览

| 项 | 内容 |
|----|------|
| 之前方案(v0.1) | EC800MCNLE 复用小智 AI 语音栈（本地 VAD/KWS/opus） |
| **本次方案(v0.2)** | **STM32(感知采集) + EC200U(通信终端/音频I/O) + 自建云端服务(全部智能)** |
| 设备端定位 | **纯输入/输出终端**，无 AI、无综合判定（仅本地基础降级） |
| 云端定位 | **唯一大脑**：STT、大模型对话、TTS 音频合成、多源数据融合决策、记忆、主动关怀 |
| 感知分工 | **EC200U 直驱板载传感器**(三轴/光敏/温湿，复用 usr/libs 驱动) + STM32 仅接额外传感器(超声/水位等，经串口) 一并上传 |

### 核心设计原则
1. **设备端"哑终端"**：EC200U 负责 4G 联网、数据汇聚上传、音频录制上传、云端返回音频的播放，不承载智能逻辑。
2. **感知"板载优先"**：EC200U 直驱其板载/可直连传感器（三轴加速度、光敏、温湿，驱动存于 usr/libs）；**只有 EC200U 不具备的额外传感器**（如超声波、水位/积水）才接 STM32 经串口上报。
3. **智能"云端化"**：AI 对话、语音合成、跌倒等综合判定、主动关怀全部在云端完成。
4. **通信"HTTP POST"**：设备→云统一走 HTTP POST（JSON 数据 / 音频二进制），云→设备由响应体返回音频与执行指令。

## 2. 系统总体架构（数据链路）

```
┌──────────────────────────── 云端服务（唯一大脑）─────────────────────────────┐
│  AI交互: STT识别 → 大模型对话/综合决策 → TTS合成 → 返回对话音频                  │
│  传感决策: 汇聚STM32+EC200U数据 → 倾倒/避障/积水/关怀 → 下发指令或合成提示音频     │
│  记忆: 短期会话 / 中期事务(用药提醒) / 长期画像(病史、称谓、偏好)                 │
└───────────────────────────▲──────────────────────────────┬──────────────────┘
                 HTTPS POST 上传                              HTTPS 响应
              (JSON传感 + 音频二进制)                 (对话音频 + 执行指令JSON)
┌────────────────────────────────────────────────────────────────────────────┐
│                       设备端 - EC200U(QuecPython 通信终端)                 │
│   ① 4G 联网               ② 数据汇聚/协议封装     ③ 音频I/O(录制/播放)      │
│   ④ STM32串口接收          ⑤ HTTP POST上传         ⑥ 执行云端指令(播报/OLED) │
└───────────────▲─────────────────────────▲──────────────────────────────────┘
        UART 串口（仅额外传感）          ADC/I2C/GPIO（板载/直连）
┌───────────────┴─────────────┐   ┌──────┴────────────────────────────────────┐
│  STM32*(可选，仅超声/水位)*       │   │  EC200U 直驱板载/直连传感器  (复用 usr/libs) │
│  超声波(HC-SR04)                 │   │  LIS2DH12 三轴加速度(跌倒原始数据) I2C      │
│  水位/积水(ADC)                  │   │  光敏 GL5528(光照/照明)          ADC        │
│  (默认无，按需引入)               │   │  温湿度 ATH20(环境/关怀)        I2C        │
│                            │   │  麦克风/喇叭(录音/播音)  OLED 蜂鸣 按键      │
│                            │   │  (充电/LBS定位/可选GPS)                     │
└─────────────────────────────┘   └──────────────────────────────────────────┘
```

### 端云链路
- **上行**：`STM32 串口帧 → EC200U`（原始传感数据）；`EC200U 本机传感`（光敏/温湿）；`EC200U 麦克风录音`。三者由 EC200U 聚合，**POST** 上传云端。
- **下行**：云端返回 **对话音频**（TTS 生成）由 EC200U 播放；同时可返回 **执行指令 JSON**（如播报提示、OLED、LCD、蜂鸣、控制）。

| **云端-传感/数据 MCP 服务器** | 自建(暴露给 Coze 调用) | Coze 通过 MCP tools 读取传感器实况、读写数据库 | ✅ 工具化 |

> 设备端在**无网络时提供最基础的本地播报降级**（预置语音/固定指令），保障基本安全兜底。
> **默认基线 = 纯 EC200U 单机（板载传感）**；超声避障/水位为**可选**外设，确有需要才引入 STM32+串口。

## 5. 通信协议设计

### 5.1 设备↔云端：HTTP REST/POST

| 端点 | 方向 | 载荷 | 响应 |
|------|------|------|------|
| `/api/audio/chat` | EC200U→云 | 麦克风音频(multipart/二进制) | **TTS 对话音频** + 指令 JSON |
| `/api/sensor/report` | EC200U→云 | 传感器 JSON(板载为主，含可选STM32项) | 决策指令(播报/告警/关怀文本) + 可选合成音频 |
| `/api/location/report` | EC200U→云 | LBS/GPS + 设备状态(电量等) | ack |
| `/api/sos` | EC200U→云 | 一键/确认求救 | 触发流程(通知/拨号指令) |
| `/api/sms` (可选云托管) | 云→家属 | 位置/状态短信 | — |

- **音频格式**：上行录制使用 EC200U `audio.Record` 产出的 PCM/WAV，或由 EC200U 边录边传分片；下行接收**服务端 TTS 合成的音频**（建议 WAV/MP3），由 `audio.Audio` 播放。
- **认证**：设备端带 `device_id`（取 IMEI）+ token，云端鉴权。

### 5.2 STM32 ↔ EC200U：串口帧协议（仅在引入 STM32 时启用）

```
帧格式：[0xAA 0x55][type(1)][len(1)][payload][校验(1)]
type: 0x01 超声距离(可选) | 0x02 水位(可选) | 0x03 三轴加速度(x,y,z) | 0x04 环境光 | ...
payload: 原始传感数据（由云端负责换算与判定）
校验: 累加和低8位
```
- STM32 按不同采样周期打包发送；EC200U 解析后与自身板载传感聚合。
- 纯 EC200U 单机（默认）无需此协议，三轴/光敏/温湿由 EC200U 直接采集。

### 5.3 云端→设备：MQTT 长连接下行（主动下发）

设备常处 4G NAT 之后、无公网端口，**云端无法主动建连打入**。采用 **MQTT 长连接**作为下行通道：设备端作为订阅者，云端发布，实现"云端随时能主动向设备说话"。

```
Coze工作流/定时任务/校准MCP ─▶ FastAPI网关 ─(发布)▶ MQTT Broker ─(订阅)▶ EC200U
                                主动关怀/SOS/待办/远端控制指令音频       常驻长连接
```

- **主题**：`cane/{device_id}/cmd`（设备专属下行）；上行 ack 可回 `cane/{device_id}/ack`。
- **负载**：JSON，`{type, text?, audio_url?, action?...}`——如关怀播报文本/音频 URL、OLED 显示、蜂鸣、SOS 联动、固件配置更新。
- **设备端**：EC200U 用 QuecPython `mqtt` 模块联网后订阅 `cane/{device_id}/cmd`，收到即解析执行（播报/显示/执行），长连+心跳保活、断线重连。
- **云端端**：FastAPI 作为发布者（paho-mqtt 等）写入 Broker；触发源可由 Coze 工作流经 MCP 发起，或在网关定时任务/告警时发起。
- **兜底**：长连异常时叠加 HTTP 长轮询 `GET /api/poll?device_id=..` 作为降级通道。

> 与既有资产一致：`usr/Qth`(QuecThing)、小智 `src/protocol.py` 均基于 MQTT，模式成熟可直接复用经验。

### 5.4 云端→设备：音频数据下发（信令与数据分离）

**MQTT 不适合直接传输较大的音频**（4G 下阻塞、耗流量）。因此把**信令**与**音频数据**分离：

- **MQTT 只传元数据**：`{type:"speak", id:"<audio_id>", audio_url:"https://.../audio/<id>.mp3", text:"..."}` —— 轻量唤醒设备准备取数。
- **设备经 HTTP GET 拉取音频**：EC200U 收到 `audio_url` 后，用 QuecPython HTTP/`urequests` GET 拉到本地文件，再交给 `audio.Audio` 播放，播完回 ack `{id, status:"played"}`。

```
Coze/TTS ─▶ 网关/对象存储(音频文件) ─▶ 步骤① MQTT信令{audio_url} → EC200U
                                              步骤② 设备 HTTP GET https://<公网>/audio/<id>.mp3
                                              步骤③ audio.Audio 播放 → 回 ack
```

**音频的"可达性"是关键**：
- 若网关/对象存储具**公网可达**（公网 IP / CDN / 对象存储 OSS / 内网穿透）→ 设备 4G 直接 GET 该 URL，最简洁。
- 若网关仅**内网** → 设备 4G 访问不到，须把 TTS 音频**上传至公网对象存储**（OSS/七牛/CDN 等），下发其公网 `audio_url`。
- **回退**：若不便搭建存储，可由设备改为 POST 请求云端 `/api/audio/fetch?id=..` 触发，由云端把音频一并返回（或返回 base64 小音频）——适合短提示音。

> 权衡：整段下载后播放最稳（不受网络抖动影响）；流式播放（边下边播）可降低首音延迟，但 QuecPython `audio.Audio` 以本地文件为主，必要时再评估。

## 6. 软件方案

### 6.1 云端服务（FastAPI 网关 + Coze 工作流 + MCP 数据打通，主干交付）

**分工（按用户确认）**：FastAPI 做**设备接入网关**；**Coze 空间/扣子编程**承载**对话智能与工作流编排**（模型对话、STT、TTS、主动关怀）；FastAPI 侧自建或托管 **MCP 服务器**，把**传感信息获取**与**数据库操作**标准化为 MCP 工具暴露给 Coze 调用 —— 让 Coze 的 Agent 能"看到"设备实时传感、能"读写"业务数据。

```
设备(POST) ──▶ FastAPI 网关 (鉴权/路由/音频转发) ──▶ Coze API (对话/工作流)
                        │   ▲                                  │  MCP tools调用
                        ▼   │                                  ▼
              DB(记录/记忆) ◀──速────────── [传感信息MCP] / [数据库MCP]
```

- **FastAPI 网关**：`/api/device/*` 接收设备上传（音频、传感 JSON、LBS、SOS）；鉴权(device_id+token)；调用 Coze 开放接口（对话流/智能体 API）获取回复文本/指令；对下行音频做 TTS（可由 Coze 或网关完成）后返回给设备。
- **Coze（扣子编程）**：搭建"关怀/避障/应急对话"智能体或工作流：STT 转文字 → 大模型多轮对话（人格化陪伴）→ 生成播报文本 / 执行指令 / 触发主动关怀。通过**添加 MCP 服务**接入自建 MCP 工具。
- **MCP 服务器（面向 Coze）**：
  - **传感信息 MCP**：tools 如 `get_sensors`(读设备实时三轴/光敏/温湿/定位)、`get_history`(历史趋势) —— 供 Coze 判断"是否跌倒/光照不足/长时间无交互"。
  - **数据库 MCP**：tools 如 `user_get`/`user_set`(画像与称谓)、`record_add`/`record_query`(会话与记忆)、`alert_insert`(告警) —— 供 Coze 读写记忆库。
  - **下行指令 MCP***(可选)*：tools 如 `push_to_device`(向设备下发播报文本/音频 URL/指令) —— 供 Coze 直接触发 MQTT 下行，实现主动关怀/提醒。
  - 实现方式：用 `fastapi-mcp` 现成库在同一 FastAPI 进程内挂载，或独立 MCP server；Coze 侧"添加 MCP 服务"填入流式 HTTP URL 即可。
- **记忆服务**：短期(会话)/中期(用药提醒定时)/长期(用户画像)——落库由数据库 MCP 或直接 DAO 完成。
- **主动关怀**：由 Coze 工作流或网关定时任务触发，Coze 根据传感/记忆发起问候/提醒，经 TTS 下发音频。

### 6.2 角色模型与权限分权（老人 / 家人 / 管理员）

**三类角色（按用户确认）**：

| 角色 | 实体 | 主要通道 | 职能 |
|------|------|---------|------|
| **老人（使用者）** | 拐杖设备端 EC200U | 设备 POST/MQTT、语音 | 使用设备、语音交互、被动接收播报与关怀、一键 SOS |
| **家人（观测与信息发送者）** | 家人手机 App | App 调云端 API | 观测老人状态/传感/告警；主动向老人设备发送消息、设定关怀/提醒 |
| **管理员（后台人员）** | 后台管理台 | Web/云端 API | 设备管理（远程控制/运维+日常运营管控）、全量数据查看、告警处置 |

**核心规则：同一设备可被绑定"1 老人 + 多名家人 + 后台管理员"；三者各持独立的 Coze 智能体（多智能体隔离），共用同一套 MCP 工具层，但通过角色化 Token 的 scope 鉴权隔离权限。**

```
             ┌─ 老人设备端(EC200U) ─0╮
             │                       ├──▶ FastAPI 网关(角色Token鉴权) ──┬─▶ Coze·老人Bot(被陪护/求助)
  家人App ────┤  家人(多) ────────────┤                                ├─▶ Coze·家人Bot(观测/关怀/提醒设置)
             └─ 管理员后台 ──────────╯                                └─▶ Coze·管理员Bot(设备运维+运营管控)
                                       │                                  │ (各自仅被授权调本角色工具)
                                       ▼                                  ▼
                                  DB(角色/绑定/记录) ◀────  MCP 工具层(带角色scope校验)
```

**（a）角色化 Token / 鉴权（按用户确认）**
- 为老人设备、每位家人、管理员分别签发 JWT，内含 sub(用户)、role(elder/family/admin)、scope(允许调用哪些 API 与 MCP 工具)、device_id(绑定设备)。
- 网关中间件校验签名/过期/scope，替代当前 x-device-token 单一静态 token；可实现撤销与到期。
- 老人设备 token 仅限"设备自身数据上报 + 本设备下行接收"；家人 token 可读"绑定设备传感/告警"+"向该设备发送消息/设关怀"；管理员 token 含全套（详见 MCP scope 表）。

**（b）Coze 多智能体分权（按用户确认）**

| Coze 智能体 | 绑定角色 token | 可调用的 MCP 工具（可见功能） |
|-------------|--------------|------------------------------|
| **老人 Bot** | elder + 设备 token | sos_trigger、record_add/query(仅本人会话)、user_get(仅本人画像)、push_to_device(仅播报本人关怀) |
| **家人 Bot** | family + 设备 token | get_sensors/get_history(观测)、alert_query/push_to_device(发送关怀/提醒/消息到设备)、user_get/set(维护老人画像)、record_add/query(留言) |
| **管理员 Bot** | admin token | 全部上述工具 + device_control(远程控制/运维+运营管控)、user_get/set(任意设备)、alert_insert/query/mark_handled(处置告警)、device_list/device_config(全量) |

> 实现：一个 FastAPI MCP 服务承载全部工具，但每个工具在被调用前做 scope 校验——解析 Coze 会话携带的角色 token，无对应 scope 则拒绝。Coze 侧"添加 MCP 服务"对三个 Bot 接入同一 URL，由后端按 token 动态放行不同工具子集。

**（c）家人↔设备"互相通信"（按用户确认：经云端转发）**

- 家人 App 发送：App → 云端 API /api/family/direct 或家人 Bot push_to_device → 网关 MQTT 发布 cane/{device_id}/cmd → 老人设备接收并播报/显示。
- 设备→家人：老人求助/回执 → 设备 POST 云端 → 网关 MQTT 发布 familymsg/{user_id}（家人 App 订阅）或推送到家人 App 的 WebSocket/长轮询。
- 统一经云端，可审计、可记录；不依赖局域网（4G 亦可用）。

**（d）管理员设备控制（按用户确认：含日常运营管控）**
- 运维级：device_control 重启/升级/参数下发/远程重启联动；（可选）远程锁定/静音。
- 运营管控级：可主动播报（问候/通知）、改设备设置（音量/免打扰时段）、介入陪护对话、调整关怀策略。范围较宽，配合管理员 Bot 的单独授权与操作留痕。

**（e）MCP 工具 → 角色 scope 映射（权限矩阵）**

| MCP 工具 | elder | family | admin |
|----------|:--:|:--:|:--:|
| get_sensors / get_history | ×（本人设备受限子集） | ✅ | ✅ |
| sos_trigger | ✅ | × | ✅ |
| user_get / user_set | 仅本人 | 绑定设备 | 任意设备 |
| record_add / record_query | 本人会话 | 留言/关怀 | 全量 |
| alert_insert / alert_query / alert_mark_handled | 触发(求救) | alert_query | alert 全操作 |
| push_to_device | 本人播报 | 绑定设备消息/提醒 | 任意设备+控件 |
| device_control（远程运维） | × | × | ✅ |
| device_list / device_config | × | × | ✅ |

**记忆归属**：老人画像/会话以 device_id 归属；家人留言/关怀记录以 (family_id, device_id) 归属；管理员操作写入 operation_log(留痕) —— 均落 SQLite 扩展表。

### 6.3 EC200U（QuecPython，通信终端）
- 主循环/事件驱动：4G 联网 → 定时上报板载传感 → 收到音频请求时录音并 POST → 播放下行音频 → 执行下行指令。
- **MQTT 下行线程**：联网后订阅 `cane/{device_id}/cmd`，长连保活、断线重连；收到下行 JSON 即执行（播报文本/音频 URL、OLED 显示、蜂鸣、SOS 联动、配置更新）。
- 串口线程 *(可选)*：若引入 STM32，接收其串口帧，缓存/聚合。
- 按键驱动：SOS 一键触发 `/api/sos`。
- **本地基础降级**：无网络时用预置音频/固定指令提供基础播报（兜底，非智能判定）。

### 6.4 STM32 固件（.c）*(可选)*
- **仅在需要超声避障/水位检测时引入**。接这些额外传感器，初始化传感器与 UART，轮询采样，按串口帧协议定时发送；**不做判定**。
- EC200U 板载传感（三轴/光敏/温湿）无需 STM32，直接由 EC200U 采集。

> 默认基线 = **纯 EC200U 单机**（板载传感满足跌倒/光敏/温湿）。超声避障/水位按需可选，需要时才增加 STM32+串口。

### 6.5 对话模式与优先级调度（老人 - AI / 家人 / 管理端）

**对话模式**：老人语音的可能"下一跳接收方"分为三类——`ai`(与 Coze AI 陪伴对话)、`family`(与家人对话)、`admin`(管理端播报)。一次语音会话命中哪种模式，由**优先级调度**决定。

**优先级（按用户确认，从高到低）**：
| 优先级 | 来源 | 说明 |
|---|---|---|
| **最高** | 管理端 TTS / 家人语音 下发 | 主动、命令/关怀性质，须立即打断/置顶 |
| **中** | 管理端 / 家人发起的文字→TTS | 需即时播报 |
| **低** | 老人与 AI 陪伴对话 | 可被任何高优先级内容抢占/排队 |

**规则（按用户确认）**：
1. **信息下发 > 主动对话**：管理端下发的 TTS、家人发的语音，优先级高于老人主动与 AI 的对话请求。当家人/管理端消息到达时，正在进行的 AI 对话被**打断并置顶**，AI 对话进入**队列/暂停**，待插播结束恢复。
2. **最新操作生效 + 提示**：设备端按键、家人 App、云端任意一方切换对话模式 → 更新云端权威状态，并**广播 MQTT 通知**其它端当前模式；收到切换的一方**语音/文本提示**"现在切换到与家人对话"。
3. **EC200U 本地 TTS 兜底**：EC200U 支持本地文本转语音，管理端/家人短文本（<~30 字）可在**无网络或低带宽**时由设备本地 TTS 播报，而非必须下载音频文件。

**状态机（设备端 EC200U / 云端协同）**
```
              ┌──────────────┐  打断/置顶(高优先级)   ┌──────────────┐
  老人语音 ──▶│ AI 对话(低)  │ ─────────────────────▶│ 家人/管理(head)│
              └──────┬───────┘                        └──────┬───────┘
                     │ 播完/超时恢复                          │ 播放完成
                     ▼                                         ▼
              AI 对话恢复排队                            回到空闲/原模式
```
- 设备端：录音上传后，云端判定当前**生效对话方**（按优先级+最新操作），决定将这段语音送去 AI / 家人 / 管理。
- 云端：维护每设备的"当前对话方"权威状态 + 一个**插播队列**（家人/管理消息排队），保障信息下发不被 AI 回话挤掉。

**家人语音双向（异步留言式，按用户确认）**：
- 家人 → 设备：家人 App 录音 → 上传 → 云端 MQTT 下发 `audio_url` + `type=family_voice` → 设备下载播放 → 播完回执。
- 设备 → 家人：老人播放家人语音后，按键/自动开启录音 → 上传 → 云端存为留言并推送家人 App。
- 说明：异步留言式（非实时对讲），可回放、可留存；对带宽/网络波动不敏感。

**电话通信（数据语音为主 + 电话兜底，按用户确认）**：
- 日常语音：走数据通道（网络 / IP 语音），复用上述模式与优先级机制。
- 电话卡兜底：EC200U 插 SIM，在**无网络或紧急情况**时家人/管理可**直接拨号**联系老人；电话作为备用通道，与网络语音并存。

**交互入口**：模式切换来源 = ① 设备端按键、② 家人 App、③ 云端(管理端)。三端都可触发，遵循"最新操作生效 + 提示"。

| 风险 | 影响 | 对策 |
|------|------|------|

| MQTT 长连接稳定性 | 断线丢指令 | 心跳保活+QoS1+断点补发（长轮询兜底）|

## 10. 结论

按"设备端=输入/输出终端，云端=唯一大脑"重构：**EC200U 直驱板载传感（三轴/光敏/温湿）**，可选 **STM32 超声/水位**（按需）→(串口)→ EC200U 汇聚上传 →(POST)→ **FastAPI 设备网关 → Coze 工作流(对话/STT/TTS/主动关怀) + 传感/数据库 MCP** → 返回音频与指令 → EC200U 播放执行。
该架构将全部智能上云，设备端逻辑大幅简化（EC200U 仅 I/O + 网络）。同时引入**老人/家人/管理员三角色权限模型（6.2）**：多智能体 Coze + 角色化 JWT scope 鉴权，实现同一设备被多人观测、家人可云端转发通信、管理员可远程运维与运营管控。**云端以 FastAPI 为接入网关，Coze 承载对话与工作流，MCP 将实时传感与数据库操作标准化暴露给 Coze**，实现"传感可视化+数据可读写"的行业务闭环。**默认基线为纯 EC200U 单机**（复用板载传感与 usr/libs 驱动），超声避障/水位作为可选外设，需要时才引入 STM32。此外引入**对话模式与优先级调度（6.5）**：管理端 TTS / 家人语音优先于老人 AI 对话（可打断排队），支持设备按键/家人 App/云端三端切换（最新生效 + 提示），EC200U 本地 TTS 兜底短文本，语音交互为异步留言式，电话卡作无网/紧急兜底。
